# Format

The visual shape of every note type the kit ships: the frontmatter block and body skeleton each type follows. A format note is that frontmatter plus one fenced skeleton, no header and no intro, since the template is self-referential. The kit ships a shape for every type it defines; none is intentionally omitted.

## Members

- [[Format-Note]] — the catch-all atomic note, the loosest shape in the set.
- [[Format-Journal]] — personal reflection, matching what transcription emits for a journal.
- [[Format-Idea]] — a single-shot capture of a spark.
- [[Format-Source]] — an external artifact another note cites.
- [[Format-Snippet]] — paste-ready functional code.
- [[Format-Reference]] — a piece of evergreen, context-free knowledge.
- [[Format-Research]] — an investigation's live, unproven findings.
- [[Format-Plan]] — the living checklist the plan skill maintains.
- [[Format-Session]] — the work log handoff writes at session end.
- [[Format-Design]] — a design standard, the functional axis.
- [[Format-Voice]] — a voice standard, the conversational axis.
- [[Format-Index]] — a note whose body links its members, this shape.
- [[Format-Project]] — an active project hub with a goal and an end.
- [[Format-Area]] — an ongoing role or system, with no start or end.
- [[Format-Format]] — the format note's own shape, the template behind this set.
- [[Format-Addendum]] — a transient edit merging into its target.
- [[Format-Revision]] — the review skill's edited working copy.
- [[Format-Log]] — the pipe-delimited operational run log.
- [[Format-Gate]] — the decision-header shape every gate file carries at its top (Changes, User Review, Filing Target), so a group review is a decision, not a rubber stamp.
- [[Format-User-Queue]] — the user-queue item shape: a `###` heading, one context line, option checkboxes; the only shape the UI's Decide bucket renders.
- [[Format-Machine-Queue]] — the machine-queue checklist shape: one `- [ ]` action per line, checked by the agent only after completion.
